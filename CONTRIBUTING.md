# Contributing

DevKitty accepts contributions that improve the product, the documentation, or the developer experience.

---

## What belongs here

- Bug fixes
- Documentation updates
- Accessibility improvements
- Performance improvements
- Tool additions
- UI refinements
- Small focused refactors

---

## Contribution standard

Every change must:

- Match the DevKitty design system
- Keep the product consistent
- Preserve accessibility
- Avoid unnecessary dependencies
- Avoid loud startup styling
- Keep the code readable and maintainable

---

## Tool work

A new tool must:

- Solve one clear problem
- Fit the existing tool architecture
- Use the shared layout and interaction patterns
- Include labels, input handling, output handling, and actions
- Include documentation when needed

---

## Pull requests

A pull request must include:

- What changed
- Why it changed
- Screenshots for UI work
- Any follow-up notes

Keep the scope small and reviewable.

---

## Issues

When reporting a bug, include:

- Browser and version
- Steps to reproduce
- Expected behaviour
- Actual behaviour
- Screenshots if useful

When requesting a tool, include:

- Tool name
- The problem it solves
- Input and output shape
- Why it belongs in DevKitty

---

## Review rules

Changes are reviewed for:

- Product fit
- Visual consistency
- Accessibility
- Performance
- Maintainability
- Documentation quality

---

## Final rule

If a change makes DevKitty less consistent, less useful, or less premium, it does not belong.
