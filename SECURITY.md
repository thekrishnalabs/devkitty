# Security Policy

## Reporting a Vulnerability

Security matters in DevKitty.

If you find a vulnerability, report it privately and do not open a public issue.

### Report details

Include:

- A short summary of the issue
- The affected file, page, or workflow
- Steps to reproduce
- Expected behaviour
- Actual behaviour
- Any screenshots or logs that help explain the problem

### What to avoid

- Do not post secrets publicly.
- Do not include private keys in reports.
- Do not open a public issue for a sensitive security problem.

---

## Response Process

Security reports are reviewed with priority.

Maintainers will assess the issue, confirm impact, and decide the safest fix path.

If needed, the reporter may be contacted for clarification.

---

## Scope

This policy covers:

- Frontend code
- Tool logic
- Documentation workflows
- GitHub repository configuration
- Build and deployment workflow assumptions

---

## Safe Disclosure

After a fix is available, responsible disclosure is preferred.

Public details may be shared once the issue is resolved and the fix is ready.
