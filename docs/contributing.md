# Contributing to DevKitty

> Clear rules for tools, docs, and product contributions.

Thank you for contributing to DevKitty.

This repository is organised as a premium developer product. Contributions must follow the same standard.

---

## What You Can Contribute

- Bug reports
- Tool requests
- Documentation improvements
- UI improvements
- Accessibility fixes
- Performance improvements
- Code quality improvements
- Small standalone utilities

---

## Before You Start

Read these files first:

- `README.md`
- `docs/vision.md`
- `docs/philosophy.md`
- `docs/roadmap.md`
- `docs/branding.md`
- `docs/design-system.md`

These documents define the product direction and contribution standard.

---

## Contribution Rules

- Keep the design system intact.
- Keep the tone calm and technical.
- Keep changes small and reviewable.
- Keep every new tool consistent with the rest of DevKitty.
- Do not introduce purple, neon, gradients, or generic SaaS styling.
- Do not add unnecessary dependencies.
- Do not break client-side-first behaviour unless there is a strong reason.

---

## Tool Contributions

Before adding a new tool:

1. Check whether the tool already exists.
2. Check whether a related tool can be extended instead.
3. Follow the standard tool page template.
4. Include clear labels, input handling, output handling, and actions.
5. Add documentation if the tool introduces new behaviour.

Each tool should solve one job cleanly.

---

## Code Style

- Use readable names.
- Keep components small.
- Reuse shared utilities.
- Keep files focused on one responsibility.
- Prefer explicit logic over clever shortcuts.

---

## Pull Request Expectations

A pull request should:

- Describe the change clearly
- Explain why it matters
- Keep scope narrow
- Include screenshots when UI changes are involved
- Mention any follow-up work if needed

---

## Issue Reports

When reporting a bug, include:

- Browser name and version
- Steps to reproduce
- Expected behaviour
- Actual behaviour
- Screenshots when useful
- Any relevant input data

---

## Tool Requests

When requesting a tool, include:

- Tool name
- Problem it solves
- Expected input
- Expected output
- Why it belongs in DevKitty

---

## Review Standard

Changes are reviewed for:

- Product fit
- Visual consistency
- Accessibility
- Performance
- Maintainability
- Documentation quality

---

## Golden Rule

If a change makes DevKitty less consistent, less readable, or less useful, it does not belong.
